# Host调用返回的条件剩余时间

`runtime/host_residual.py`拟合可观测的外层worker host调用从进入到返回/异常的持续时间分布。它输出**到host返回的受限期望剩余秒数**，不是GPU完成、batch进度、token里程碑或耦合内核的`remaining_fraction`。没有将它接到策略或评分。

## 可识别目标与迟到观测

令D为host调用总持续时间，a为采样时已持续时间，l为采样至决策的延迟。已知的是`D>a`，不是`D>a+l`。如果S是按组拟合的未返回概率，则决策后H秒内的受限期望剩余量为

`integral[a+l, a+l+H] S(t) dt / S(a)`。

这保留“采样后、收讫前可能已经返回”的概率`1-S(a+l)/S(a)`；不能错误地重新条件化为决策时仍运行，也不能从旧host栈伪造as-of进度。H外还有概率质量时完整均值为null，不能把受限均值充作完整残余时间。

每组按持续时间排序：风险集含同一时刻的返回、异常与右截尾；先结算返回风险，再移去该时刻全部记录。异常是单独保留的终止原因，不当正常成功。右截尾保留而非丢弃；若最后仍有未返回概率，查询超出已观测支持区间则拒绝并仅提供已识别的下界。不凭常数延伸尾部。右截尾内推仍依赖组内独立截尾假设，不能由算法本身证明。

支持门同时检查采样年龄之后的风险集数量与不同case数；总体样本多不等于长调用尾部有支持。分组使用service、DP rank、TP lane与host调用种类，不偷看真实未来输出长度。模型与训练数据绑定hash，不把其它lane或调用类型作为缺失组的默认值。

## 本次真实数据用途

`tools/fit_host_residual.py`按预先写下的`residual-exploration-protocol-20261110.json`处理r4：24个case全部保留，12个timing-off标为无观测。原始文件先与既有验收成员SHA匹配，提取execute/sample/dummy全部外层调用；嵌套子scope不重复计账。输入错误中止并留下报告，不能筛掉坏case继续宣称全量有效。

顺序回放每个timing-on case时，只用严格更早已结束case训练；当前case及未来case不得进入模型。虚拟查询按绝对monotonic原点的100ms网格生成，不按调用最终长度选百分位。H固定2秒，风险集至少20调用且来自3个case。回放采用零收讫延迟，**不是实际live socket观测或真实可用时刻**；运行时数学另测非零延迟。早期无训练、长尾无支持、截尾和失败查询均逐行保留，覆盖率与有支持点的误差分开报告。

这是对已经查看过的r4所做的新探索拟合；不是独立holdout、实时部署能力或15%/30%预测门验收。同节点/进程相关性、遗漏batch/peer工作负载及timing-on观测扰动仍可能使模型不可泛化。即使host残余误差好，也不能证明联合request-seconds预测有效。
