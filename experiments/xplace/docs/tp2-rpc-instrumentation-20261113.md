# RPC关联诊断候选：本地实现，尚不可部署

修订位于`evidence/ep4-tp2-ablation-20261111/rpc-instrumentation-20261113-r0/candidate`，独立复制自r9。旧上传包、已验收原始数据和原分析器均未改动；未提交GPU作业，也不把本地测试当作科学验收。

## 本次补齐的观测边界

- 默认关闭`XPLACE_RPC_DIAGNOSTICS`。启用后，每轮四个scheduler组件各有独立关联ID，绑定model和DP rank；只把观测上下文中的`placement_snapshot`路由到专用诊断入口，不改变普通控制请求。
- 记录控制器进入、utility协程开始等待/返回/取消、生产端wrapper进入/结束和客户端可用时间。utility开始等待不是实测线缆发送时刻，wrapper进入也不是engine IPC到达时刻，仍不能把复合区间直接解释成单一根因。
- 生产端维护独立有界历史；客户端取消后，正在执行或稍后执行的生产调用仍可记录结束。历史通过既有engine观测socket导出，依赖同钟、producer身份和关联ID匹配。
- 成功调用的紧凑时间元数据独立于整个部分快照保留，避免r9中62个成功快照被省略后连时间戳也不可用。没有返回结果的调用仍保持缺失，不从生产端历史填成成功响应。
- 每轮增加可取消的deadline回调探针，区分“回调未触发”和“回调迟到”；不将未触发记为零延迟，也不称它为GPU或生产端执行时间。

## 固定界限与已知丢失

原80ms deadline、100ms周期、28组件、每组件16阶段、64KiB部分结果及512MiB collection界限不变。既有socket仍限4096字节；历史导出最多2048字节且按剩余消息空间缩小。scheduler紧凑元数据每项最多1024字节，随原collection事件一起计入512MiB界限。这些是序列化/条目界限，不是实际CPU RSS保证。

每个engine保留64条生产记录。该容量在10Hz名义速率下对应6.4s，大于r9观测到的1.602s取消生命周期，但不是未来负载保证。旧记录淘汰、活动记录阻塞新记录、单次导出省略均有显式计数；不能声称历史全程无损。生产进程在最后一次导出前退出，尾部证据仍可能缺失。

## 验证范围与未完成项

38项针对性测试通过，覆盖取消前已开始的生产调用、取消后才开始的调用、错误及重复身份、有限历史、实际socket消息上限、部分结果省略后保留紧凑时间、整轮取消和默认关闭时的r9格式兼容。

隔离回归使用原来预注册的571项非分时启动清单，加38项新诊断测试，609项全部通过且精确身份一致，耗时93.95s。隔离副本只含运行代码、测试、输入及显式SHA绑定的本地cloudpickle测试依赖；源文件前后不变，CPU子进程5s限制未放宽。最初两个夹具失败及一次测试收集失败均已定位、修复并保留原回执；这些通过不能解释或抹去历史CPU5s失败，也不代表GPU验证。

候选仍有`HOLD`，不具备提交条件：

1. 需要最终生产端尾部持久化，以及跨样本历史的去重、缺口、重启身份和迟到关联验收；不得把缺失历史补成已发生或把取消重标为完成。
2. 需要独立schema2分析器与其测试。r9分析器只接受旧阶段集合，不能直接用于新候选。
3. 候选中复制的571项启动契约及r9部署清单仍是历史输入，必须重新生成、校验并冻结新清单后才能部署；不能借用旧提交或恢复脚本。
4. 新诊断的真实开销、覆盖率、CPU/RSS和容量均未在GPU验证。测量修订不代表实测代价接入、严格消融或完整系统优越性通过。

原r8/r9科学拒绝及CPU5s失败继续保留，不放宽工作负载、内存、timeout或验收门槛，不启动混合拓扑。
