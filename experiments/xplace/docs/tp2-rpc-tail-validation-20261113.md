# RPC收尾与独立关联校验：r1本地候选

新修订位于`evidence/ep4-tp2-ablation-20261111/rpc-instrumentation-20261113-r1`。它从已冻结r0复制，未修改r0、r9、原始结果或主runtime。仍有HOLD，未部署、提交或申请allocation；所有科学门槛保持false。

## 收尾时序与边界

收集器原有stop、trace cutoff、请求取消清理和事件关闭逻辑保持原位。`run_causal_calibration`在`run_trace`清理结束后，显式执行一次收尾采集，再沿已有路径保存`collection.json`。只读取四个既有engine观测socket，不新增utility RPC，不重新打开collection事件流，也不改变请求状态或原完整率分母。

收尾继续使用80ms协作式timeout；不是硬实时墙钟保证。四路读取成功、失败、超时及外部取消均只尝试一次，保留每个slot的状态，不自动重试。外部取消时先保留已取得或已取消的证据，再传播取消；finally仍执行报告保存。

每路socket上限4096字节，journal导出最多2048字节。收尾整体保留上限16KiB，且必须与已保留事件共同落在原512MiB payload上限内；不足时记录`omitted_byte_limit`，不增大原预算。收尾状态元数据是报告管理字段，不是CPU RSS保证。64KiB部分快照、16阶段、28组件、100ms周期及CPU子进程5s限制均未放宽。

journal在同一锁内记录`captured_at`，用于校验导出发生在生产记录之后、客户端可用之前。收尾仍然只是有界历史的最后一次可见快照，可能省略保留记录；不是生产端排空证明。采集结束后才执行的调用、进程被杀或最后一次导出前丢失的历史仍可能缺失。`producer_quiescence_proven=false`和`future_activity_unknown=true`明确保留。

## 独立校验范围

`analysis/rpc_reconcile.py`不导入候选runtime，独立校验schema2组件身份、阶段与部分结果界限、紧凑时间、deadline回调、journal序号/计数和收尾保留账目。完整率、客户状态和所有原始输入不改写。

- 跨样本按同钟、model、DP rank、producer ID和PID分组，处理重复观察、running到returned/error的演进及生产身份变化；不把新身份的序号1接到旧身份末尾。
- 丢失序号区间、淘汰、拒绝、导出省略及未匹配生产记录分别保留。导出省略的累加不是唯一丢失条数；没看到生产记录不等于调用未执行。
- 同序号改换关联ID、已终结状态反转、计数回退、身份冲突、时钟不一致及错误字节账目均拒绝。
- 取消客户可以匹配到取消后才进入/结束的独立生产记录，但客户仍然是cancelled，原轮仍然不完整。成功紧凑元数据缺少journal时也不补造生产历史。
- 未触发deadline回调仍记未知，而不是零延迟。客户端utility等待不是线缆派发，wrapper进入不是engine IPC到达；本修订不证明生产端瓶颈或TTFT因果。

## 本地验证与保留的问题

50项运行侧针对性测试通过。完整隔离回归由原609项非分时身份加12项收尾测试组成，621项在95.10s通过，精确身份及候选/隔离副本SHA一致。58项独立分析测试在另一隔离副本中通过，含真实本地engine socket、全28组件、取消后才开始的生产调用、冲突/重启/缺口、字节上限及布尔伪schema对抗测试。58项分析身份也精确核验；针对性测试是回归子集，不能重复累加。

本轮最初把规范化Slurm状态回执误作带stdout的传输回执，触发本地KeyError；在任何写入、复制、测试或网络动作前中止。错误留证后改为追随SHA绑定的transport指针核验；没有重查集群或重取结果。全部测试尝试和产物保留，不抹去历史CPU5s超时及r8/r9科学拒绝。
