# r9 部分传输的隔离恢复（2026-11-12，第70次续接）

本修订仅修复部署传输，不改变冻结的 GPU 包、571 项启动身份或 207 项分析测试绑定。r9 仍是组件诊断 pilot，不是正式性能验证；不能与 r8 跨修订配对。

## 已知失败与边界

上一轮传输 240s 超时、TERM 10s 后 KILL；远端 940032/1655236 字节与本地同长度前缀逐 SHA 一致。原网络原因和原写入者全局退出状态均未知。失败原件、日志、HOLD、部署锁以及 189 个 PAUSE 不变。

原 CPU 子进程 5s 超时根因仍未证明。容量压力估算 572.70MiB 超过 512MiB 的失败保留；源码路径估算 483.30MiB 不是未来 GPU 容量保证。r8 的覆盖率和 TTFT 负结果不变，全部科学门槛仍为 false。

## 恢复协议

1. 复用冻结的旧路径隔离器：仅对精确匹配的部分文件进行改名，保留 quarantine 和只读前缀快照。旧 `upload-r0.tar.gz` 路径永久保持缺失，迟到的原写入者即使完成旧 inode 也不能通过原路径 SHA 校验或发布。
2. 新传输使用不同的 `upload-r1.tar.gz`，本地直接以只读普通文件作为 SSH stdin；远端独占锁和 noclobber 禁止覆盖。保留起止时间、输入 SHA/字节、远端接收字节和最终 SHA。文件偏移量仅代表本地读取，不是远端交付证明。
3. 新传输时限 900s，结束后 TERM 10s，再 KILL。此前约 940032 字节/240s 的观测只能支持增加传输余量，不能证明网络已修复。900s 仅为一次性传输上限，不改变 CPU 5s、采样 80ms/100ms、64KiB/512MiB 或 allocation 1h。
4. 独立目录解包，核对完整归档、精确成员集合、清单及逐文件 SHA；文件先只读，目录在独占的私有暂存路径保留 rename 所需权限。`mv -n` 发布后整树只读，再复验并写成功标记。已有目标不覆盖。
5. 提交绑定新恢复回执，沿用冻结的资源、环境变量及通用 `.submit-once` 锁。实际提交前且不早于查询下限，仅执行一次旧作业 sacct 和用户空队列 squeue 守卫。未知或失败结果禁止自动重试，无提交后立即轮询。

旧发布成功标记一律拒绝。只有隔离后出现的旧部署非零退出码可作为失败证据保留；零值、非整数及多行值均拒绝。未完成隔离前，旧隔离器的严格条件不放宽。

## 本地失败与修复

- 首次组合测试 97 通过、16 失败，结果与源码快照保留：`set -e` 不会对 `&&` 左侧失败自动退出；只读目录的跨父目录 rename 在本机失败；`grep` 单行命中不能证明整个退出码合法；`wc` 可以通过文件长度优化而不读取 stdin。
- 修复为逐条独立 `test`、私有目录在原子发布前保留写权限、整串退出码检查，以及实际读取输入的测试夹具。第二轮 109 通过、4 失败暴露本机 Bash 3.2 对 `if` 内最后一个 `[[ ]]` 的 errexit 行为；改为显式 `exit 1`，保留复现结果。
- 最终测试加入新授权 SHA、前置回执、提前查询拒绝、进程创建失败和并发本地锁；实际结果以 `component-recovery-20261112-r1/tests-r2.json` 为准，未通过不得远端执行。原 r0 的 55+14 项保护测试一起回归。
