# TP2 失败轮次组件诊断修订

## 原因与边界

`313797` 与 `315554` 的双顺序块仍被科学验收拒绝：八组配对覆盖率为 78.77%–86.78%，Code TTFT 最差采集开销为 +17.77%。反向块 1,634 个失败采样轮次均缺少组合 transport；其中 1,629 轮仍有 batch-link 观测。成功样本的耗时不能代表失败样本，也不能定位失败轮次的具体慢组件。

本修订只为下一次诊断 pilot 增加缺失证据，并修正任务清理和迟到结果判定。它没有 GPU 结果，不表示覆盖率、采集开销、实测代价模型或正式系统性能已通过。原始两个块、所有截尾请求、负结果和冻结分析器不变。

## 记录契约

- 每个 `sample` 增加 `component_diagnostics`。通过任务局部 `ContextVar` 绑定当前轮次，嵌套任务继承，退出后恢复；不改 worker 热路径，也不增加 RPC。
- 双模型 DP2/TP2 每轮应有 28 条组件记录：4 个 scheduler RPC、12 个 execution endpoint、12 个 batch-link endpoint。记录模型、DP rank、角色和适用的 TP rank。
- 保存本地单调时钟域、开始/结束时间及阶段时间点。RPC 分为发起、返回、校验；endpoint 分为路径、连接、读取、校验、关闭。阶段差值是主机侧历时，不是 GPU 忙时。
- socket 字节量只统计已收到的 payload；未读完或 RPC 无线级字节观测时明确为未知，不能记为零。失败轮次保存的 `result_json_bytes` 是结果 JSON 编码大小，不是网络传输量。
- 子任务状态区分完成、超时、取消和不可用。`received_before_deadline` 与 `completed_before_deadline` 分开保存；收到数据但清理晚于截止，不被标成完整按时完成。
- 只有失败或不完整轮次才额外保存可取得的子结果；成功轮次不重复复制已存在于 transport 的数据。诊断字段始终是 `diagnostic_only=true`、`prediction_input_eligible=false`，不填补原 transport，也不提高 `transport_complete`。

每轮最多 64 个组件、每组件 16 个阶段；额外子结果的累计 JSON 字节最多 65,536。组件/阶段超限、子结果超限或无法编码均有显式计数或状态，不默默丢弃。整体仍受原采集事件数和 512 MiB 字节上限约束；CPU 上限不等于 GPU 作业中不会触发保留上限，仍须实测验收。

## 截止与清理差异

采样周期仍为 100ms，截止仍为 80ms。共同截止明确锚定 `collect_round` 开始时刻，包含发起准备时间；迟到但恰好赶在事件循环超时回调前返回的组合结果标记为 `DeadlineExceeded`，不算完整采样。这是更严格的边界检查，不回算或改写 r8 的旧覆盖率。

组合任务成功、异常和取消路径均收取父 gather 与所有子任务结果，等待其协作式清理，避免遗留未收取的 gather future。清理可能越过采样截止，不能把清理完成时间当成按时收到数据；不声称能强制终止拒绝取消的协程。r8 的清理警告仍保留，CPU 回归不能证明 GPU 环境中的警告根因已完全解决。

## 验证与提交限制

定向验证覆盖四类慢组件、部分完成、外部取消、真实 Unix socket 阶段/字节/关闭、精确截止边界、事件循环迟到、任务上下文隔离及保留上限。首轮 108 项定向测试通过。

扩大回归沿用冻结的 549 项非分时启动选择，再加入 22 项新测试。独立副本 **571 项通过**；本地首次完整回归为 **570 通过、1 失败**，22 项新测试全部通过。具体结果及身份审计记入 `evidence/ep4-tp2-ablation-20261111/component-diagnostics-20261112-r0/`。不运行被移除的分时测试选择。

本地失败是未修改的 `test_real_cpu_child_exit_logs_and_returncode[0]`：最小 CPU 子进程在原 5s 时限内未产生 stdout/stderr，随后被 SIGTERM 回收。失败原始文件保留于 `failed-cpu-child-r0/`。冻结版与当前版分别在新进程中对照该测试，两个退出码各通过，但这不能消除首次完整回归失败，也不能证明启动延迟根因已修复。未修改 `causal_job.py`、该测试或其时限；本修订仍不可直接提交 GPU。

独立副本首次准备因继承冻结目录的只读权限失败，尚未启动测试；失败回执保留。仅将新建测试副本设为可写后应用补丁，原冻结上传目录不变。

本修订未打包或提交 GPU 实验。`isolated/` 只是 CPU 测试副本：其中旧提交脚本、manifest 和启动契约不代表新修订可部署。下一步须在新 tag 下绑定新增模块、完整测试身份、源码差异、诊断字节容量和诊断协议，再考虑一个不超过一小时的 allocation。不得重放原提交，不得把诊断 pilot 当作 holdout 或正式消融；EP4TP2 的实测代价与独立配对门槛未过前不启动混合拓扑。
