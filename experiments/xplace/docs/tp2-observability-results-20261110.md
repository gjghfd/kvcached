- 对每个长间隔，计算各worker上≥100ms的host execute/sample/dummy调用区间的并集覆盖率，再取八个lane的最小值。84个间隔的该最小覆盖率中位97.51%，范围0–99.82%；其中4个为0、6个低于50%，不删除这些例外。
- Code decode期间，活跃案例中的worker execute调用最长18–25ms量级；较长host等待主要出现在sample/dummy区间，最长约1.066秒。这里是host方法边界，**不是CUDA kernel完成时间**，不能直接判定GPU排队、collective或具体内部同步的责任。
- 84个间隔中均有至少一个worker host返回，83个有Conv worker host返回；返回通常可出现在间隔末端，不能把“有返回”解释为全程持续、平滑的GPU进展。

以上将调查重点从“只有前端输出不可见”缩小到worker采样/dummy调用内的等待，但不排除较小前端延迟，也没有证明单一GPU/collective根因。独立重算核验了223,752个原始worker调用配对、全部长间隔覆盖及返回计数，无诊断helper复用。事后heartbeat区间可能在gap结束后才被观测到；本分析只作回顾性机制描述，不能直接作为在线特征或未来信息oracle。
